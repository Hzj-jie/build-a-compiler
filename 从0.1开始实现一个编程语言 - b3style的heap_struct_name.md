# 从0.1开始实现一个编程语言 - b3style的heap_struct_name

之前[b3style_b2style_self_test](https://github.com/Hzj-jie/osi.net/blob/be159b71db42c81064b234faf3b0a2d1959c8226/service/tests/compiler/b3style/b3style_b2style_self_test.vb#L27-L30)因为b3style还不支持`heap_struct_name`，而忽略`static_cast`相关的测试，

```vb.net
' Missing heap-struct-name - assertion failure
r = r OrElse unordered_set.of("static_cast_ptr_type3.txt",
                              "static_cast_ptr_type_bool.txt",
                              "static_cast_ptr_type.txt").find(name).is_not_end()

```

那么就可以先支持这个语法。其实`static_cast_ptr_type2.txt`也因为同样的原因不能执行，不过这里注释不够准确。 

`heap_struct_name`可以用在两个地方，第一是作为变量，另一个是调用堆上的结构体的函数，对应两种不同的测试。

作为变量，比如[static_cast_ptr_type.txt](https://github.com/Hzj-jie/osi.net/blob/master/service/tests/compiler/b2style/self-test/static_cast_ptr_type.txt)，读写堆上的结构体的变量。

```cpp
#include <b2style.h>
#include <testing.h>
#include <b2style/to_str.h>

struct S {
  int x;
  string y;
};

void f(S s) {
  for (int i = 0; i < 10; i++) {
    b2style::testing::assert_equal<int>(s[i].x, i);
    b2style::testing::assert_equal<string>(s[i].y, b2style::int_to_str(i));
  }
}

void f(type_ptr p) {
  static_cast(p, S);
  f(p);
}

void main() {
  S s[10];
  for (int i = 0; i < 10; i++) {
    s[i].x = i;
    s[i].y = b2style::to_str(i);
  }
  static_cast(s, type_ptr);
  f(s);
  b2style::testing::finished();
}

```

作为堆上结构体的函数，比如[class_on_heap.txt](https://github.com/Hzj-jie/osi.net/blob/master/service/tests/compiler/b2style/codegen/class_on_heap.txt)，调用`cs[i].print()`。 

```cpp
#include <b2style.h>
#include <b2style/stdio.h>

class C {
  int x;
  string y;

  void print() {

	b2style::std_out(this.y);
  }

  C x;
  int y;

  void print() {

	b2style::std_out(" ");

    cs[i].x.y = b2style::int_to_str(i);

  }

  for (int i = 0; i < 100; i++) {
    cs[i].print();

}

```

`heap_struct_function_call`和`ignore-result-heap-struct-function-call`对应函数调用，`heap_struct_name`对应堆上的结构体的变量。和普通的函数一样，是否在意函数返回值并不影响主要的调用过程，所以`heap_struct_function_call`和`ignore-result-heap-struct-function-call`都是在`heap_struct_function_call`中实现的。

先来看[heap_struct_name](https://github.com/Hzj-jie/osi.net/blob/master/service/compiler/b3style/logic/nodes/heap_struct_name.vb)，首先这是个`heap_name`，类似于b2style中的处理方式，`a[i].b`对应堆上的`a.b[i]`。

```vb.net

End Class

```

 所以可以看到这两个步骤，`b2style.heap_struct_name.logic_order`和`heap_name.as_raw_variable_name`。

[b2stye.heap_struct_name.logic_order](https://github.com/Hzj-jie/osi.net/blob/89eec7be6196626ff3858c74ca50c77b8a7cb296/service/compiler/b2style/rewriter/nodes/heap_struct_name.vb#L16)是个简单的重构，注意到bstyle完全遵从logic语言上对堆空间的处理，所以这里`bstyle_order`和`logic_order`是一个概念。这个函数把`a[i].b`变成`a.b`和`i`两个部分，保存在一个`tuple`中。 

```vb.net
' Return name + index_node
Public Shared Function logic_order(ByVal n As typed_node) As tuple(Of String, typed_node)

    assert(n.child(0).child_count() = 4)

                                       n.child(1),
                                       n.child(2)).

                                            Return x.input_without_ignored()
                                        End Function).
                                    collect_by(stream(Of String).collectors.to_str("")).
                                    ToString(),
                            n.child(0).child(2))
        End Function

```

这里的处理不是非常准确，不过暂时可以使用。最重要的问题是`x.input_without_ignored()`。

可以看到这里解决了两个主要问题，第一，堆和栈的类的变量本身在展开时处理是不同的，一个是`raw_variable_name`，另一个是`heap_name`。第二，查找`a[i].b`是否是个`delegate`的逻辑被推后了，因为`is_heap_name`的判断断言`[i]`在最后。这里能看出一个明显的问题，`a[i].b`不可以是`delegate`, 不过这个语法现在并没有用到，可以之后再处理。

这两点之外，其实虽然代码改动很多，原理却很简单，就是让`a[i].b(c)`变成`::b(a[i], c)`，同时保证`a.b(c)`仍然是`::b(a, c)`。或者说最重要的一行其实是，
