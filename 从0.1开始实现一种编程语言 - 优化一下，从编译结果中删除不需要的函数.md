# 从0.1开始实现一种编程语言 - 优化一下，从编译结果中删除不需要的函数

至此为止，b2style把代码编译成bstyle的代码，bstyle把代码编译成logic的代码，logic再把代码编译成primitive的指令序列。因为编译完成的指令序列总是从`main`这个函数开始，有些代码就有可能不会被用到，但编译过程中并不会考虑这个问题。

比如说

```cpp
#include <b2style.h>
void main() {
  b2style::std_out("abc");
}

```

这是一个非常简单的程序，`main`使用到的只是`b2style.h`中的`b2style::std_out(string)`这个函数。但[b2style.h](https://github.com/Hzj-jie/osi.net/blob/master/service/compiler/b2style/lib/b2style.h)包含大量的代码， 把这些代码通通编译进最终的primitive指令序列中虽然并不会带来非常显著的性能问题，但编译过程本身浪费的时间却是可观的，毕竟编译任何一段代码都是复杂的字符串匹配的过程。

如此一个简单的优化就是把没用的代码剔除掉，不过删除什么和从哪一层删除却是有意思的问题。既然上面提到没用的函数，那么可以从删除没有用到的函数开始。虽然比如不可能达到的代码之类的也是可以删除和优化的，暂时不考虑。

```cpp
#include <b2style.h>
void main() {
  if (false) {
    b2style::std_out("abc");
  }
}
// 这段代码可以优化成一个空的main函数。

```

再考虑从哪删除，如果要处理起来简单的话，自然是从完全没有函数重载的logic编译器中实现。不过这样就表示b2style和bstyle的编译器都会生成大量无意义的代码，而bstyle和logic的编译器也都会花费大量的时间编译这些无用的代码。但是b2style通过bstyle的函数重载实现类，b2style编译器本身并不能理解函数重载。这么说的话，在bstyle的编译器上实现删除无用函数是个比较好的选择。

简单说来从任何一个函数开始，需要执行的代码都是个树状结构。

- 因为logic，bstyle和b2style都没有链接过程，若`func_a`调用`func_b`，`func_b`需要在`func_a`之前定义，从而使`func_b`无法调用`func_a`。所以调用关系不是一个图。

判断一个函数在最终的primitive指令序列中是否有用，只需要考虑其是否在`main`为根的树上即可。所以首先实现一个[scope.call_hierarchy](https://github.com/Hzj-jie/osi.net/blob/master/service/compiler/scope.call_hierarchy.vb)类，用以记录编译中碰到的函数调用关系，基本上就是一个字符串到字符串列表的字典。

```vb.net
Partial Public Class scope(Of T As scope(Of T))
    Public MustInherit Class call_hierarchy
        Private ReadOnly main_name As String
        ' To -> From
        Private ReadOnly m As New unordered_map(Of String, vector(Of String))()
        Private ReadOnly tm As New unordered_map(Of String, Boolean)()
' ...
        Public Sub [to](ByVal name As String)
            assert(Not name.null_or_whitespace())
            Dim from As String = current_function_name().or_else(main_name)
            assert(Not from.null_or_whitespace())
            name = name.Trim()
            from = from.Trim()
            If Not name.Equals(from) Then
                m(name).emplace_back(from)
            End If
        End Sub

```

在bstyle生成一个`function`的代码时，不是直接写入结果中，而是写入一个中间类型。如果最后无法在`call_hierarchy`中找到这个函数，就忽略它。

```vb.net
 Private NotInheritable Class filtered_writer
    Private ReadOnly ch As call_hierarchy
    Private ReadOnly f As String
    Private ReadOnly o As Func(Of String)

    Public Sub New(ByVal ch As call_hierarchy, ByVal f As String, ByVal o As Func(Of String))
        assert(Not ch Is Nothing)
        assert(Not f.null_or_whitespace())
        assert(Not o Is Nothing)
        Me.ch = ch
        Me.f = f.Trim()
        Me.o = o
    End Sub

    Public Overrides Function ToString() As String
        If (scope_arguments.remove_unused_functions Or True) AndAlso Not ch(f) Then
            Return empty_string
        End If
        Return o()
    End Function
End Class

```

注意这里面有个flag，--remove-unused-functions，可以关闭这个功能。这是有意义的，比如生成一个.o和.so的时候，这个功能就要关闭，这个之后再说吧。

`call_hierarchy`提供功能来判断一个函数是不是可以被`main`函数引用到。上面的`string->bool`的字典可以缓存查询结果。 

```vb.net
 Default Public ReadOnly Property can_reach_root(ByVal f As String) As Boolean
    Get
        assert(Not f.null_or_whitespace())
        f = f.Trim()
        If f.Equals(main_name) Then
            Return True
        End If
        Dim it As unordered_map(Of String, Boolean).iterator = tm.find(f)
        If it <> tm.end() Then
            Return (+it).second
        End If
        Dim r As Boolean = False
        Dim it2 As unordered_map(Of String, vector(Of String)).iterator = m.find(f)
        If it2 <> m.end() Then
            Dim v As vector(Of String) = (+it2).second
            assert(Not v.null_or_empty())
            For i As UInt32 = 0 To v.size() - uint32_1
                If can_reach_root(v(i)) Then
                    r = True
                    Exit For
                End If
            Next
        End If
        tm(f) = r
        Return r
    End Get
End Property

```
