# 从0.1开始实现一种编程语言 - 简单的预展开模板

在各种语言中模板有不同的名字，比如java和c#中叫`generics`，c++和d中叫`templates`。从用户角度来看似乎并没有太大区别，除了语法。不过这里还是要区分一下这两种实现，一个称为类型擦除，一个称为类型展开。

如其名，类型擦除的实现中，模板类型参数在模板本身中是不存在的；类型展开的实现中，模板类型参数在类型的实现中是存在的。这可以解释为什么类型擦除的模板实现需要类似类型限制，而类型展开的模板实现无法简单的编译为独立的包。这样说还是非常抽象，还是举个例子吧。

## 类型擦除

```java
// java
public class MyClass {
    interface I {
      void print();
    }
    
    static class C<T extends I> {
      void print(T t) { t.print(); }
    }
    
    static class D implements I {
      public void print() { System.out.println("D"); }
    }
    
    public static void main(String args[]) {
        C<D> c = new C<>();
        D d = new D();
        c.print(d);
    }
}

```

这里的`class C<T extends I>`基本等同于

```java
static class C {
  void print(I i) { i.print(); }
}

```

当然实现上还有一些细节，比如c#的类型限制支持`where T: new()`这样的有限的“非类型”的限制；还有类似`T getter()`这样的函数可以返回一个`T`的引用而不是`I`的。c#中对此的支持要稍微明确一些，使用`in`和`out`关键字来标识模板类型的父类或子类是否可以在特定的地方被使用。java则简单的用`extends`和`super`来让用户控制这个限制。虽然细节上有些差别，编译器都可以简单的把上面的`class C<D extends I>`编译为`class C`的包，再加上一些有限的元数据，比如这个`D`是否有`new()`的限制。

## 类型展开

```cpp
// c++
#include <iostream>
template <typename T>
class C {
  public: void print(const T& t) { t.print(); }
};

class D {
  public: void print() const { std::cout << "D" << std::endl; }
};

int main() {
  C<D>().print(D());
}

```

这里`C`的`typename T`不需要任何“限制”就可以使用`T`的`print()`函数。而如果`C<D2>`中的`D2`没有`print()`函数，编译就会失败。所以这里`C<D>`可以基本上可以被认为是

```cpp
class C_D {
  public: void print(const D& t) { t.print(); }
};

int main() {
  C_D c;
  D d;
  c.print(d);
}

```

如果另一个类型`C<D2>`在某处被引用，编译器就会生成`class C_D2`，而`void print(const D2& t) { t.print(); }`就可以让编译器直接判断`D2::print`是否存在。

所以`template <typename T> class C<T>`压根不存在在编译器的输出中，也就没法编译成独立的包，编译器也没法仅通过头文件的定义就展开模板。所以比如`#include <vector>`就不是`#include <vector.h>`。

虽然不再需要类型限制，但是类型展开的模板实现也有明显的缺陷，除了前面说到的无法编译为独立的包，还有个问题就是同样的代码会被重复多次，每个模板的类型展开都生成一份独立的代码，这严重影响编译速度和生成的代码的大小。不过还有个好处就是这样的模板实现没有任何运行时的性能影响，展开的模板类可以直接调用模板类型参数的任何代码而不需要查找任何类型信息。

既然b2style是类c++的语言，所以实现的也是类似c++的类型展开的模板。完整的c++的模板相当的复杂，比方说模板的“类型参数”可以不是类型，而是一个类型的实例。

```cpp
#include <iostream>
template <int I>
class C {
  public: void print() { std::cout << I << std::endl; }
};

int main() {
  C<1>().print();
  C<2>().print();
}

```

或者模板类型的模板类型以及不定长模板类型。

```cpp
#include <iostream>
#include <set>
#include <vector>
template <template <typename...> typename T>
class C {
 public: template <typename... D> void print(const T<D...>& t) { std::cout << t.size() << std::endl; }
};

int main() {
  C<std::set>().print(std::set<int>());
  C<std::set>().print(std::set<long>());
  C<std::vector>().print(std::vector<int>());
}

```

这些功能对b2style来说太复杂了，也没有太大的必要。简化的功能支持到如下这个例子，包含模板的类型展开和嵌套。这个例子本身也是一个测试（[service/tests/compiler/b2style/codegen/nested_template.txt](https://github.com/Hzj-jie/osi.net/blob/master/service/tests/compiler/b2style/codegen/nested_template.txt)）。

```cpp
#include <b2style.h>

class C {
  void print() {
    b2style::std_out("C");
  }
};

template <T>
class D {
  void print(T t) {
    t.print();
  }
};

template <T, T2>
class E {
  void print(T t, T2 t2) {
    t.print(t2);
  }
};

void main() {
  C c;
  D<C> d;
  E<D<C>, C> e;
  e.print(d, c);
}

```

开始实现之前有些杂七杂八的小改动，目标就是把`name`和`type-name`区分开， 主要在

[Implement type-name in shared/syntaxer_rule.txt · Hzj-jie/osi.net@603b3b1](https://github.com/Hzj-jie/osi.net/commit/603b3b1dd5a9aa046f63c2bc932ae4c1428a5978)

[Move name and type-name into syntaxer · Hzj-jie/osi.net@2528732](https://github.com/Hzj-jie/osi.net/commit/2528732b27678903752c932b360df793d3c0d565)

之后当然是nlexer和syntaxer的规则文件，nlexer中只有一个新的关键字`template`，syntaxer中则要考虑模板定义和类型使用两个部分。

```text
raw-type-name [double-colon]? [raw-name-with-double-colon]* raw-name
template-type-param-list [template-type-param-with-comma]* template-type-param
template-type-param-with-comma template-type-param comma
template-type-param raw-type-name
template-type-name raw-type-name less-than template-type-param-list greater-than
type-name [template-type-name, raw-type-name]

root-type [..., class, template]
type-param-list [type-param-with-comma]* type-param
type-param-with-comma type-param comma
type-param raw-name
template kw-template less-than type-param-list greater-than class

```

这是第一个版本的实现，不支持模板嵌套模板，所以`template-type-param raw-type-name`，后一个版本会改成`template-type-param type-name`。

代码上也自然分成两部分，一部分是记录模板定义，另一部分是展开模板。

## 模板定义

这里用到了一个[template_template.vb](https://github.com/Hzj-jie/osi.net/blob/master/service/compiler/b2style/template_template.vb)，名字有点拗口，不过确实是“模板的模板”。这个类型有两个基本的功能，

```vb.net
' 从template typed_node生成自身
Public Shared Function [of](ByVal n As typed_node, ByRef o As template_template) As Boolean

' 用类型参数展开一个类的实现
Public Function apply(ByVal types As vector(Of String), ByRef impl As String) As Boolean

```

基本上来说就是把`typed_node`中和模板类型参数相同的`raw-type-name`置换成占位符，再在`apply`的时候把占位符换成对应的类型。剩下的是一些实现的细节，比如检查类型数量是否一致，用`class_name_t`和`ref<string>`避免重复的字符串查找等。这中间需要用到`typed_node::dfs`深度优先搜索以自动搜索所有的`raw-type-name`节点。

```vb.net
Private ReadOnly w As New template_writer()
Private ReadOnly class_name As class_name_t
Private ReadOnly types As New vector(Of ref(Of String))()

Private Sub New(ByVal n As typed_node, ByVal types as vector(Of String))
' ...
    n.dfs(Sub(ByVal node As typed_node, ByVal stop_navigating_sub_nodes As Action)
              assert(Not node Is Nothing)
              assert(Not stop_navigating_sub_nodes Is Nothing)
              If Object.ReferenceEquals(n.child(1), node) Then
                  ' type-name of class.
                  assert(w.append(class_name))
                  stop_navigating_sub_nodes()
                  Return
              End If
              If Not node.type_name.Equals("raw-type-name") Then
                  Return
              End If

              For i As UInt32 = 0 To types.size() - uint32_1
                  If node.input().Equals(types(i)) Then
                      assert(w.append(Me.types(i)))
                      stop_navigating_sub_nodes()
                      Return
                  End If
              Next
          End Sub,
          Sub(ByVal leaf As typed_node)
              assert(Not leaf Is Nothing)
              assert(w.append(leaf.word().str()))
          End Sub)
End Sub

```

## 在b2style.template中记录模板的定义

和`class`的实现类似，b2style的`scope.template_t`记录已经处理的所有模板。每个`scope`有自己的`template_t`的实例， 所以模板的定义有有效范围。

因为主要功能都在`template_template`中实现了，`scope.template_t`的功能相对简单，只用到[reparser](https://github.com/Hzj-jie/osi.net/blob/master/service/compiler/code_gen/reparser.vb)把生成的`class`再通过`class`的实现重新编译一次。

```vb.net
Private NotInheritable Class class_reparser
    Inherits code_gens(Of typed_node_writer).reparser(Of b2style.parser)

    Private ReadOnly m As unordered_map(Of String, definition)

    Public Sub New(ByVal m As unordered_map(Of String, definition))
        assert(Not m Is Nothing)
        Me.m = m
    End Sub

    Protected Overrides Function dump(ByVal n As typed_node, ByRef s As String) As Boolean
        assert(Not n Is Nothing)
        assert(n.child_count() = 4)
        Dim name As String = template_type_name_name(n)
        Dim d As definition = Nothing
        ' The definition should be searched already in resolve.
        assert(m.find(name, d))
        assert(Not d Is Nothing)
        Dim types As vector(Of String) = template_type_name_types(n)
        ' TODO: Should resolve type-aliases.
        If Not d.injected_types.emplace(types).second() Then
            ' Injected already.
            s = empty_string
            Return True
        End If
        Return d.template.apply(types, s)
    End Function
End Class

```

其中reparser的概念就是“当前的b2style的代码生成器生成的仍然是b2style的代码，再用b2style把生成的代码编译一次”。

## 模板展开

在处理到`template_type_name`节点的时候，对应的code_gen会把展开的实现嵌套进代码中并用带有模板参数类型的新的类的名字取代模板名称本身，比如用`C_D`取代`C<D>`。

```vb.net
 Public Function build(ByVal n As typed_node,
                      ByVal o As typed_node_writer) As Boolean Implements code_gen(Of typed_node_writer).build
    assert(Not o Is Nothing)
    Dim extended_type As String = Nothing
    If Not scope.current().template().resolve(n, extended_type) Then
        Return False
    End If
    o.append(extended_type)
    Return True
End Function

```

主要的改动大约就是这些，在[Implement template in b2style · Hzj-jie/osi.net@a91679d](https://github.com/Hzj-jie/osi.net/commit/a91679d412bde7899f71bedcf1c425f76aea10e9)

## 允许模板的嵌套

前面提到以上的这个实现不支持模板的嵌套，还有个不大不小的改动以支持模板的嵌套。最主要的改动在于模板展开的时机，在`scope.template_t.resolve`的时候允许递归调用自身。

```vb.net
Private Shared Function template_type_name_types(ByVal n As typed_node,
                                                 ByRef o As vector(Of String)) As Boolean
    assert(Not n Is Nothing)
    assert(n.child_count() = 4)
    o.renew()
    Dim v As vector(Of String) = o
    Return streams.range(0, n.child(2).child_count()).
                   map(Function(ByVal index As Int32) As typed_node
                           Return n.child(2).child(CUInt(index))
                       End Function).
                   map(Function(ByVal tn As typed_node) As typed_node
                           If tn.type_name.Equals("template-type-param-with-comma") Then
                               Return tn.child(0)
                           End If
                           Return tn
                       End Function).
                   map(Function(ByVal tn As typed_node) As Boolean
                           assert(tn.type_name.Equals("template-type-param"))
                           tn = tn.child().child()
                           If tn.type_name.Equals("raw-type-name") Then
                               v.emplace_back(tn.children_word_str())
                               Return True
                           End If
                           Dim r As String = Nothing
                           If Not scope.current().template().resolve(tn, r) Then
                               Return False
                           End If
                           v.emplace_back(r)
                           Return True
                       End Function).
                   aggregate(bool_stream.aggregators.all_true)
End Function

```

改动主要在[Allow nested template · Hzj-jie/osi.net@0ef52aa](https://github.com/Hzj-jie/osi.net/commit/0ef52aadb364cc14398d6940489c3e3cc8c77f11)。

注意到这样模板的实现只是简单的字符串替换，所以支持如c++中的“类型实例”的模板参数，比如`int`作为模板参数，也并不复杂，原理是一样的。

现在的实现有个小问题，`typedef`是在bstyle中实现的，所以b2style不知道C<int>和C<Integer>实际上是一回事，所以会生成两份代码。除非在b2style中也实现[scope.type_alias](https://github.com/Hzj-jie/osi.net/blob/master/service/compiler/bstyle/scope.type_alias.vb)，不然这个问题无法解决。当然也没有什么影响，除了生成的代码的大小和编译的时间。
