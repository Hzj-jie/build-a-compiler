# Building a Programming Language from 0.1 - b3style_b2style_b3style_self_test

As mentioned in [Zijie He: Building a Programming Language from 0.1 - Supporting bstyle in b3style](https://zhuanlan.zhihu.com/p/639883836), we can substitute `b3style` for `bstyle` as the backend that compiles the `bstyle` code generated by `b2style` into the `logic` language—which is a bit of a mouthful.

To recap: `b2style` compiles source code into `bstyle` code, which `bstyle` then compiles into `logic` code, and finally `logic` compiles it into a sequence of `primitive` instructions. Because `b3style` is a superset of `bstyle`, even before `b3style` fully implements `b2style`'s syntax, it can already replace `bstyle` in this pipeline.

[service/compiler/b2style/b2style.vb](https://github.com/Hzj-jie/osi.net/blob/master/service/compiler/b2style/b2style.vb)

```vb.net
Partial Public NotInheritable Class b2style
' Compile b2style output using bstyle
    Public NotInheritable Shadows Class parse_wrapper
        Inherits rewriter_rule_wrapper(Of nlexer_rule_t,
                                          syntaxer_rule_t,
                                          __do.default_of(Of vector(Of Action(Of statements))),
                                          suffixes_t,
                                          rewriter_gens_t,
                                          scope).parse_wrapper
        Public Sub New(ByVal functions As interrupts)
            MyBase.New(functions)
        End Sub
        Protected Overrides Function text_import(ByVal s As String, ByVal o As exportable) As Boolean
            Return bstyle.with_functions(functions).parse(s, o)
        End Function
    End Class

' Compile b2style output using b3style
    Public NotInheritable Shadows Class parse_wrapper_b3style
        Inherits rewriter_rule_wrapper(Of nlexer_rule_t,
                                          syntaxer_rule_t,
                                          __do.default_of(Of vector(Of Action(Of statements))),
                                          suffixes_t,
                                          rewriter_gens_t,
                                          scope).parse_wrapper

        Public Sub New(ByVal functions As interrupts)
            MyBase.New(functions)
        End Sub

        Protected Overrides Function text_import(ByVal s As String, ByVal o As exportable) As Boolean
            Return b3style.with_functions(functions).parse(s, o)
        End Function
    End Class
End Class
```

In theory, the execution results of the two generated `primitive` instruction sequences should be identical—what we previously referred to as weak equivalence—or the generated `logic` code itself should be identical, which is strong equivalence. Given how the current `b3style` subset is implemented, the two should be strongly equivalent. Either way, it does not really matter; implementing `b2style.parse_wrapper_b3style` is simply an easy way to boost test coverage for `b3style`.

Everything after that is quite straightforward: we just parameterize all `b2style` tests—either via a template type parameter or a constructor parameter—to select the corresponding `parse_wrapper`. For example, [service/tests/compiler/b2style/b2style_self_test.vb](https://github.com/Hzj-jie/osi.net/blob/master/service/tests/compiler/b2style/b2style_self_test.vb):

```vb.net
<test>
Public NotInheritable Class b2style_self_test
    Inherits b2style_self_test_runner

    Protected Overrides Function parse(ByVal functions As interrupts,
                                       ByVal content As String,
                                       ByRef e As executor) As Boolean
        Return b2style.with_functions(functions).parse(content, e)
    End Function

    Protected Overrides Function with_current_file(ByVal filename As String) As IDisposable
        Return b2style.parse_wrapper.with_current_file(filename)
    End Function
End Class
```

And its counterpart [service/tests/compiler/b3style/b3style_b2style_b3style_self_test.vb](https://github.com/Hzj-jie/osi.net/blob/master/service/tests/compiler/b3style/b3style_b2style_b3style_self_test.vb):

```vb.net
<test>
Public NotInheritable Class b3style_b2style_b3style_self_test
    Inherits b2style_self_test_runner

    Protected Overrides Function parse(ByVal functions As interrupts,
                                       ByVal content As String,
                                       ByRef e As executor) As Boolean
        Return New b2style.parse_wrapper_b3style(functions).parse(content, e)
    End Function

    Protected Overrides Function with_current_file(ByVal filename As String) As IDisposable
        Return b2style.parse_wrapper_b3style.with_current_file(filename)
    End Function

    Protected Overrides Function ignore_case(ByVal name As String) As Boolean
        assert(Not name.null_or_whitespace())
        Return name.Equals("struct-and-primitive-type-with-same-name.txt")
    End Function
End Class
```

Both run the exact same test cases, differing only in the compilation pipeline used. A few tests may not be supported in `b3style`, as seen in the `ignore_case` function above, which we will return to shortly.

Naturally, some of these tests failed at first because a few syntax rules had not yet been wired up:

```vb.net
                with(Of reinterpret_cast)().
                with(code_gen.of_ignore_last_child(Of logic_writer)("b2style-sentence-with-semi-colon")).
                with(Of dealloc)().
                with(Of undefine)().
                with(code_gen.of_children(Of logic_writer)("value-with-bracket", 1)).
                with(code_gen.of_input_without_ignored(Of logic_writer)("paramtype")).
                with_of_all_childrens("paramtypelist").
                with(code_gen.of_first_child(Of logic_writer)("paramtype-with-comma"))
```

Like the others, `reinterpret_cast`, `dealloc`, and `undefine` are generated from `bstyle`'s code via `sed` replacement, while the remaining rules simply delegate to child nodes.

Finally, there is this test: [service/tests/compiler/b2style/self-test/struct-and-primitive-type-with-same-name.txt](https://github.com/Hzj-jie/osi.net/blob/master/service/tests/compiler/b2style/self-test/struct-and-primitive-type-with-same-name.txt)

```cpp
#include <b2style.h>
#include <testing.h>

typedef int INT;

struct INT {
  int x;
};

void main() {
  INT i;
  i.x = 100;
  b2style::testing::assert_equal<int>(i.x, 100);
  b2style::testing::finished();
}
```

This is non-standard syntax ([https://onlinegdb.com/UezoP9Dbl](https://onlinegdb.com/UezoP9Dbl)), even though `bstyle` previously happened to allow it. So for now, we simply ignore this test case when testing `b3style`.

The main code changes are in [commit/b8f09e3b157bc31f05eb9a9affebb47ebde8f432](https://github.com/Hzj-jie/osi.net/commit/b8f09e3b157bc31f05eb9a9affebb47ebde8f432).
