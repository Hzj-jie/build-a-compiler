# 从0.1开始实现一个编程语言 - b3style_b2style_self_test

超过七个月的PR，[Implement b3style_b2style_self_test with skipped tests](https://github.com/Hzj-jie/osi.net/pull/103/files)

虽然实现的细节有些变化，但self_test是在b2style中已经实现的概念，[从0.1开始实现一种编程语言 - b2style_self_test](https://zhuanlan.zhihu.com/p/462594228)。简单说来就是把代码合并成一个tar文件，然后依次编译和运行，[service/tests/compiler/compiler_self_test_runner.vb](https://github.com/Hzj-jie/osi.net/blob/master/service/tests/compiler/compiler_self_test_runner.vb)。其下有两种不同的测试，一种依赖于模仿注释的`// ERROR: `和`// ERROR PATTERN: ` 来测试编译错误，另一种则是依赖stdout判断代码执行的输出是否符合预期。

那么很显然，要想让b3style支持b2style_self_test，即实现b3style_b2style_self_test，实现模板函数是必须的。实现自然不能复制粘贴，那么来看一下差别在于什么。

首先b3style是bstyle和b2style的集合，即支持b2style语法，但是和bstyle一样生成logic代码。注意到logic代码的callee总是有返回值，虽然caller可以忽略，但logic只关心栈空间是否分配，所以在生成logic代码时就有`function_call.build`和`function_call.without_return`的差别。

[service/compiler/logic/callee.vb#L52](https://github.com/Hzj-jie/osi.net/blob/858973ad033229a4b75bbef13fad213455e231df/service/compiler/logic/callee.vb#L52)

```text
while_then not-finished {
    subtract i i 1
    caller copy-one-byte1 ( source i 1 )
    more not-finished i 0
}

copy i length
more not-finished i 0
while_then not-finished {
    subtract i i 1
    define result type*
    caller copy-one-byte2 result ( source target2 i 1 )
    move target2 result
    more not-finished i 0
}

```

但这在b2style的function_call中是不存在的，因为是否需要接受返回值是由语法定义的，并且转译成bstyle的代码。而同时b3style/function_call_with_template是sed自b2style/function_call_with_template，这里就涉及到这个PR中可能可以算是最重要的一个改动，即让b3style/function_call_with_template支持without_return，但又不影响b2style/function_call_with_template。这是一个工程上的小技巧。

无法执行的分成四类，

1. linked-list.txt，这是个小bug，之后会说到。
2. 没有实现`heap-struct-name`
3. 没有实现模板类
4. b2style的代码中使用logic语句的没有改成b3style的命名空间命名 - 这里注释有点不太准确
5. b2style中不可以，但b3style可以检测到的编译错误。

[service/tests/compiler/b2style/self-test/define-class-constructor-for-non-class.txt](https://github.com/Hzj-jie/osi.net/blob/master/service/tests/compiler/b2style/self-test/define-class-constructor-for-non-class.txt)

```cpp
#include <b2style.h>
#include <testing.h>

void construct(int& this, int v) {
  this = v + 1;
}

void construct(int& this) {
  this.construct(1);
}

void destruct(int& this) {}

void main() {
  int x(100);
  int y();
  b2style::testing::assert_equal<int>(x, 101);
  b2style::testing::assert_equal<int>(y, 2);
  b2style::testing::finished();
}

```

因为b2style只是简单的把类的构造和析构函数转换成`construct`和`destruct`的调用，所以这段代码在b2style中是成立的，但b3style更加严格的判断类是否存在，就可以返回编译错误了。
