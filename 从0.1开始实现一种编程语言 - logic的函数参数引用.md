# 从0.1开始实现一种编程语言 - logic的函数参数引用

前文中曾经提到bstyle和b2style都不支持函数参数引用，函数参数都是值传递。如果需要支持类，这样显然是不行的，类的函数无法在值传递的情况下修改类的实例的值，这就限制了类的功能。所以要想实现有意义的类的功能，函数参数引用是必须的。同时之前也提到i++和++i不能修改i本身的值，这也同样可以通过参数引用实现。

先回忆一下函数是怎么编译的，在函数入口的时候，函数认为当前的栈顶和其下的若干个栈空间是函数的参数和返回值。具体的实现细节可能会略有不同，比如对于void函数是不是也有返回值的位置，或者参数的压栈顺序什么。不过这些都是些细节了，基本的原理是函数本身是不可能知道调用方调用时使用的参数的位置，所以调用方会把参数都压入栈以便函数使用。

也因为同样的原因，函数无法使用调用方的栈空间，虽然事实上这是同一个栈，只是位置不同。

但是参数引用，或者说传入传出参数，其要求是参数值可以作为函数的输入，同时函数执行时对其的修改可以反馈到调用方的变量。比方说

```c
void f(int x) { x++; }
void f2(int& x) { x++; }
void main() {
  int y = 100;
  f(y);
  ASSERT_EQ(y, 100);
  f2(y);
  ASSERT_EQ(y, 101);:
}

```

这里f2函数内对x的修改会反馈到传入参数，main的y变量。而f函数内对x的修改不会有这个效果。

无论f或者f2函数，其中的x都是位于栈顶（假设void返回值不需要占用栈的位置），这两个函数也同样不能直接操作main的y变量，它们都不知道main的y变量到底在栈的什么位置。

简单说来有两种方式来实现参数引用，

1. 传入参数的位置而不是参数本身。所以引用只是指针的一种使用。
2. 考虑一下函数的返回值，引用参数也可以用同样的方式实现。函数的调用结束后，调用方在弹栈之前将栈的内容复制回参数所使用的变量。

不过首先，之前提到过，bstyle和b2style是无法实现logic语言没有实现的某些功能。这里的参数引用属于这个范畴，所以需要在logic语言中实现。

再来看一下这两个实现方法。第一个方法需要实现一个特殊的指针类型，第二个方法则相对简单，不需要增加一个特定的类型。同时假如需要实现属性，调用方需要再调用参数的属性函数，如此则只能使用第二个方法。

```cpp
// 假设c++中实现了property。
class C {
  public:
    void property set_x(int x) {
      this->x = x;
    }
    int property get_x() {
      return this->x;
    }
  private:
    int x;
};

void f(int& x) { x++; }

int main() {
  C c;
  c.x() = 1;
  f(c.x());
  /*
    等价于：
    int x = c.get_x();
    f(x);
    c.set_x(x);
  */
  ASSERT_EQ(c.x(), 2);
}

```

虽然暂时并没有实现属性的计划，不过我还是实现了第二个方法。

正如前文所说，这个功能在logic语言中实现，并且只需要修改调用方（caller），修改就在[osi.net/commit/4d12dc2fba69e206b2ce39afdcf6481de3b4277f](https://github.com/Hzj-jie/osi.net/commit/4d12dc2fba69e206b2ce39afdcf6481de3b4277f)中。

主要修改了两个文件[service/compiler/logic/builder/builders.vb](https://github.com/Hzj-jie/osi.net/blob/master/service/compiler/logic/builder/builders.vb)和[service/compiler/logic/caller.vb](https://github.com/Hzj-jie/osi.net/blob/master/service/compiler/logic/caller.vb)

（后来还有些别的不太相关的修改，这两个文件的链接指向最新的版本。）

builders.vb中需要知道函数的定义中的参数是不是引用。这里用了和c++一样的标记方式&。

```vb.net
Public NotInheritable Class parameter
' ...
    Public ReadOnly ref As Boolean

    Public Sub New(ByVal type As String, ByVal name As String)
        assert(Not type Is Nothing)
        assert(Not name Is Nothing)
        type = type.Trim()
        name = name.Trim()
        assert(Not type.null_or_whitespace())
        assert(Not name.null_or_whitespace())
        'TODO: Try to avoid allowing only "&" as parameter type.
        'assert(Not type.Equals(type_ref_suffix))
'----------------------------
        Me.ref = type.EndsWith(type_ref_suffix) AndAlso Not type.Equals(type_ref_suffix)
        If Me.ref Then
            Me.type = type.Remove(type.Length() - 1)
        Else
            Me.type = type
        End If
'-----------------------------
        Me.name = name
    End Sub

```

重要的修改是用分隔符包围的部分，引用本身不构成一个类型，所以引用符号会被从类型中剔除，但记录下此参数是不是引用。

同样关键的部分也被分隔符包围，操作和返回值基本一样，如果一个参数是引用，就把结果再复制回参数所用的变量。

除此以外，还有一个小优化。因为primitive处理器在mov操作的时候效率远比cp要高。所以如果一个参数是引用，传入时会把原来的值移动到栈顶的位置而不是之前的复制。当然这只是一个优化，对结果没有影响。

最后加个logic的测试

```text
callee m type0 ( n type*& i type* ) {
  append n i
}

define n type*
define i type*
copy_const i sd

caller m ( n i )
caller m ( n i )
caller m ( n i )
caller m ( n i )

define temp_string type*
interrupt stdout n temp_string

```

这个测试使用一个叫m的函数，其中第一个参数n是引用，用append命令将第二个参数i拼接到n的后面。初始i的值是d这个字符，调用四次后，n的结果应该是四个d字符，用stdout中断输出。

```vb.net
Public NotInheritable Class import_executor_callee_ref
    Inherits import_executor_case

    Private Shared ReadOnly io As New console_io.test_wrapper()

    Public Sub New()
        MyBase.New(_import_executor_cases.callee_ref.as_text(), New interrupts(+io))
    End Sub

    Protected Overrides Sub check_result(ByVal e As not_null(Of simulator))
        MyBase.check_result(e)
        assertion.equal(io.output(), New String(Convert.ToChar(100), 4))
    End Sub
End Class

```
