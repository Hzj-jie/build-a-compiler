# 从0.1开始实现一个编程语言 - b3style_b2style_compile_error_test

完成b3style的模板语法分析后，至少检测编译错误应该是很简单的事情。事实上也是很简单，唯一值得说到的只有[service/compiler/b3style/logic/nodes/class_initializer.vb](https://github.com/Hzj-jie/osi.net/blob/master/service/compiler/b3style/logic/nodes/class_initializer.vb)中的一小段代码。

这里有一段很大的注释，简单说来就是之前总是认为析构函数可以顺利被生成，所以用的是断言。但注意到实现的细节中，这段代码是在`scope.current().when_end_scope`时执行，是一个`IDisposable`的应用。即便中间的编译失败了，这段代码仍然会执行。但编译失败可能表示这个类压根不存在，`b2style.function_call.build_struct_function`亦会失败。有两种可能理论上来说会触发这种情况，第一个比较简单，这个类型压根不是类，比如下面的例子，也是注释中提到的[b2style_compile_error_test.reinterpret_cast_without_type_id](https://github.com/Hzj-jie/osi.net/blob/master/service/tests/compiler/b2style/codegen/errors/reinterpret_cast_without_type_id.txt)

```cpp
#include <b2style.h>
#include <b2style/stdio.h>

class S {
  int x;
  void print() {
    b2style::std_out(this.x);
  }
};

struct S2 {
  int x;
};

// This function should not be used.
void f(S& s) {
  s.x = 0;
}

void f(S2& s) {
  s.x = 100;
}

void main() {
  S s;
  s.x = -100;
  s.print();
  reinterpret_cast(s, S2);
  f(s);  // s.S2__struct__type__id should be missing here.
  reinterpret_cast(s, S);
  s.print();
}

```

这里的问题是当第一个`reinterpret_cast(s, S2)`时，S类型本来就无法转换成S2类型，因为`s.S2__struct__type__id`不存在，只有`s.S__struct__type__id`。 可以看[reinterpret_cast.txt](https://github.com/Hzj-jie/osi.net/blob/master/service/tests/compiler/b2style/codegen/reinterpret_cast.txt)中的使用方式。

```cpp
void main() {
  S s;
  s.x = -100;
  s.print();
  S2__struct__type__id__type s.S2__struct__type__id;
  // Note: this is not a typical way of using reinterpret_cast, it's pretty much useless without the support of // inheritance.
  reinterpret_cast(s, S2);
  f(s);
  reinterpret_cast(s, S);
  s.print();
} 

```

而即便编译错误，在b3style中，析构函数仍然会被生成，而`s.S2__struct__type__id`不存在，导致`function_call.ignore_parameters.without_return`的错误。

一个更简单的例子[reinterpret_cast_to_a_different_class_type](https://github.com/Hzj-jie/osi.net/blob/master/service/tests/compiler/b2style/codegen/reinterpret_cast_to_a_different_class_type.txt)使用`reinterpret_cast`和`undefine`来产生b2style可以编译的代码，而触发析构函数的b3style则仍然会检测出编译错误。

```cpp
#include <b2style.h>

class S {
  int x;
};

struct S2 {
  int x;
};

void main() {
  S s;
  S2__struct__type__id__type s.S2__struct__type__id; 
  reinterpret_cast(s, S2);
  undefine(s.S__struct__type__id);
  // On b3style, it will also complain the destruction of s as S2 cannot be generated.
  // b2style would only complain the S2__struct__type__id hasn't been defined.
}

```
