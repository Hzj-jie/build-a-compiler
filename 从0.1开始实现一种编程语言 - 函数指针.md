# 从0.1开始实现一种编程语言 - 函数指针

函数指针也是类的继承中必不可少的一个部分，用以实现函数的继承，这个到时候再说。这本身是个相对大的概念，一层一层的来考虑。

## primitive处理器

先回忆一下`jump`指令，这个指令跳转到一个特定的指令位置，这个位置本身是一个常量，可以用于函数调用，因为函数的入口位置在生成的指令序列中是固定的。不过函数指针则不同，需要跳转到的位置是一个内存地址中的值。所以首先得有个新的指令，这个指令类似于x86指令集中的`jmp eax`。

定义这个指令为

```text
jmpr	data_ref	#jump to instruction @(*A int64)
jump	data_ref	#jump to instruction @(A int64) 

```

对比`jump`的指令，后者用`data_ref`本身，前者用`data_ref`指向的内存中的值。类似的对比是`cp`和`cpc`，前者将一个地址中的值复制给另一个地址，后者将一个常量复制给一个地址。 

在primitive中添加指令，绝大多数都是自动生成的代码，重要的代码是如何执行`jmpr`指令本身。

```vb.net
Partial Public NotInheritable Class [jmpr]
    Implements instruction

    Public Sub execute(ByVal imi As imitation) Implements instruction.execute
        Dim s As Int64 = imi.access_as_int64(d0)
        imi.instruction_ref(s)
        imi.do_not_advance_instruction_ref()
    End Sub
End Class

```

这些改动主要在[commit/612d61a6174f72b7ba5802b028be1bdeb12d3d71](https://github.com/Hzj-jie/osi.net/commit/612d61a6174f72b7ba5802b028be1bdeb12d3d71#diff-cc1575e4ee760253cf84c598c76a7e7a17ee08b4b62b62428fa4b7e9b58e1503R529)。里面还包括了logic语言的改动。

## logic语言

`jmpr`只在处理器层面上提供了跳转的可能，真正可用的函数指针还需要考虑几个问题。

- 如何定义一个函数指针

定义和调用函数的时候需要记录函数的签名，以保证调用时参数和返回值的类型和预期匹配，在函数指针上也有类似的需求。当然也可以简单的使用一个`uint`来标记函数地址，然后接受调用方提供的任何参数，不过这样通常来说会导致在函数中的参数和返回值的位置没有意义，并且无法检测出错误，所以不可取。

所以简单说来，需要定义一个函数指针的类型，用以标记参数列表和返回值。通过这个类型可以定义若干个指针，这些指针本身只是`uint`类型。

这些操作应该由一个`callee_ref`语句实现，和`callee`类似，`callee_ref`也有名称，返回类型和参数列表，不过参数列表本身只需要类型而不需要变量名。

```text
# define a callee / function reference with name, parameters:
#  callee_ref f int ( a uint )
#  a type suffixed by "&" indicates that it's a "reference".
callee_ref	string	string	parameters

```

这里的注释有点错误，应该只是`( uint )`。

对比`callee`的定义，`callee`中包含有`paragraph`。 

```text
# define a callee / function with name, parameters and body:
#  callee f int (a uint) { return f a; }
#  a type suffixed by "&" indicates that it's a "reference".
callee	string	string	typed_parameters	paragraph

```

- 如何绑定一个函数指针

如上所说，一个函数指针本身可以存储一个函数的入口位置。这个存储的过程对应primitive只是一个`cpc`的指令，不过logic语言中需要做的是，1）检查函数指针和函数本身的签名是否一致，2）找到函数的入口位置，3）生成`cpc`指令。

上述这些操作可以由一个logic语句实现，称之为`address_of`

```text
# copy the position of a function:
#  address_of target source
address_of	string	string

```

- 如何调用一个函数指针

也和`caller`语句类似，有两个新的`caller_ref`语句。

```text
# execute a function based on its address with parameters and store its return value:
#  caller_ref f return-value (p1, p2)
caller_ref	string	string	parameters

# execute a function based on its address with parameters and discard the return value:
#  caller_ref f (p1, p2)
caller_ref	string	parameters

```

前一个保留返回值，后一个忽略返回值。

和primitive的指令类似，这些语句的代码也大多都是自动生成的，需要实现的也只是这几个语句本身的功能。

主要的实现都在[osi.net/commit/612d61a6174f72b7ba5802b028be1bdeb12d3d71](https://github.com/Hzj-jie/osi.net/commit/612d61a6174f72b7ba5802b028be1bdeb12d3d71#)，[osi.net/commit/e862c6dc3534cb356a770ab3a0d637d8f88ef825](https://github.com/Hzj-jie/osi.net/commit/e862c6dc3534cb356a770ab3a0d637d8f88ef825)和[osi.net/commit/3694ff299679cc0a1b824f345bd4c0e04075f5d2](https://github.com/Hzj-jie/osi.net/commit/3694ff299679cc0a1b824f345bd4c0e04075f5d2)，其中也包含了一些杂七杂八的改动。

### logic/scope.anchor_ref

和logic中的anchor一样，`callee_ref`也需要记录下定义。稍有不同的是，anchor中每个函数只有唯一的入口，而anchor_ref中，一个`callee_ref`可以绑定多个变量。

- [Implement interrupter/primitive.jmpr and logic.address_of/callee_ref/… · Hzj-jie/osi.net@612d61a](https://github.com/Hzj-jie/osi.net/commit/612d61a6174f72b7ba5802b028be1bdeb12d3d71#)中的实现和c的函数指针类似，每个`callee_ref`是唯一的指针，不过这样的实现之后会比较麻烦，说到b2style实现的时候再说。

所以anchor_ref自然有两个字典，一个存储定义，一个存储变量。变量的存储和scope.variable中的是相似的。anchor_ref中存储一个变量的函数指针类型，而scope.variable中永远存储的是uint类型。

先来看看anchor_ref自身的定义。[osi.net/scope.anchor_ref.vb at master · Hzj-jie/osi.net](https://github.com/Hzj-jie/osi.net/blob/master/service/compiler/logic/scope.anchor_ref.vb)

```vb.net
Public NotInheritable Class anchor_ref
    Inherits function_signature

    Public Sub New(ByVal name As String,
                   ByVal return_type As String,
                   ByVal parameters() As builders.parameter_type)
        MyBase.New(name, return_type, parameters)
    End Sub

    Public Sub New(ByVal name As String,
                   ByVal return_type As String,
                   ByVal parameters As const_array(Of builders.parameter_type))
        MyBase.New(name, return_type, parameters)
    End Sub

    Public Function with_begin(ByVal begin As Func(Of data_ref)) As anchor
        Return New anchor(name, lazier.of(begin), return_type, parameters)
    End Function
End Class

```

`anchor_ref`是一个`function_signature`，有返回值，名称和参数列表。不过可以通过`with_begin`函数转换为一个可以被调用的`anchor`。

`scope.anchor_refs()`保存所有的函数指针定义和指针变量。

```vb.net
Private NotInheritable Class anchor_ref_t
    ' type -> anchor_ref
    Private ReadOnly decls As New unordered_map(Of String, anchor_ref)()
    ' variable name -> anchor_ref
    Private ReadOnly defs As New unordered_map(Of String, anchor_ref)()

```

前者在`callee_ref`定义时使用，后者在`define，address_of，caller_ref`时使用。

### logic/callee_ref

### logic/address_of

如上所说，这个语句要做三件事[service/compiler/logic/address_of.vb](https://github.com/Hzj-jie/osi.net/blob/master/service/compiler/logic/address_of.vb)

```text
' TODO: Check the consistency of both signatures.
Public Function build(ByVal o As vector(Of String)) As Boolean Implements instruction_gen.build
    Dim t As variable = Nothing
    If Not variable.of(target, o, t) OrElse
       Not t.is_assignable_from_uint32() Then
        Return False
    End If
    Dim a As scope.anchor = Nothing
    If Not scope.current().anchors().of(name, a) Then
        errors.anchor_undefined(name)
        Return False
    End If
    assert((+a.begin).on_stack())
    assert((+a.begin).absolute())
    o.emplace_back(instruction_builder.str(command.cpc, t, New data_block((+a.begin).offset())))
    Return True
End Function

```

首先查找目标变量，并且目标变量需要是至少uint32。

再查找指向的anchor。

最后生成`cpc`指令，把anchor地址写进目标变量中。

当然还可以有第四件事，就是检查anchor和anchor_ref的定义是不是一样。不过这个不太重要，还没实现。

### logic/caller_ref

`caller_ref`调用`jmpr`以实现跳转，这个和`caller`基本一样，可以共用大量代码，只有两点不同。1）指令，`jump` vs `jmpr`，2）生成`anchor`的方法，`caller_ref`通过`anchor_ref.with_begin`，后者直接查找`scope.anchor`。

[osi.net/caller_ref.vb at master · Hzj-jie/osi.net](https://github.com/Hzj-jie/osi.net/blob/master/service/compiler/logic/caller_ref.vb)

```vb.net
Public Sub New(ByVal name As String,
               ByVal result As String,
               ParamArray ByVal parameters() As String)
    MyBase.New(command.jmpr, result, parameters)
    assert(Not name.null_or_whitespace())
    Me.name = name
End Sub

Protected Overrides Function retrieve_anchor(ByVal o As vector(Of String),
                                             ByRef anchor As scope.anchor) As Boolean
    Dim f As Func(Of scope.variable_t.exported_ref) =
        Function() As scope.variable_t.exported_ref
            Dim d As scope.variable_t.exported_ref = Nothing
            If Not scope.current().variables().export(name, d) Then
                Return Nothing
            End If
            Return d
        End Function
    If f() Is Nothing Then
        errors.anchor_ref_undefined(name)
        Return False
    End If
    Dim r As scope.anchor_ref = Nothing
    If Not scope.current().anchor_refs().of(name, r) Then
        Return False
    End If
    anchor = r.with_begin(Function() As data_ref
                              Return f().data_ref
                          End Function)
    Return True
End Function

```

### logic/define

如果`define`语句定义的是一个函数的指针的变量，那么行为会有些差别。首先定义的是uint32，齐次要把定义转发到`scope.anchor_ref`中。

```vb.net
 Private Function define_callee_ref(ByVal o As vector(Of String)) As Boolean
    Return define_variable(scope.type_t.ptr_type, o) AndAlso
           scope.current().anchor_refs().define(type, name)
End Function

Public Function build(ByVal o As vector(Of String)) As Boolean Implements instruction_gen.build
    If define_variable(type, o) OrElse define_callee_ref(o) Then
        Return True
    End If
    errors.type_undefined(type, name)
    Return False
End Function

```
